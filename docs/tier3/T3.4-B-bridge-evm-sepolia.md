# T3.4-B — HTLC atomic-swap bridge (real Sepolia)

**Status:** ✅ shipped in branch `tier-wow-and-3/main-block`.
**Sibling ticket:** T3.4-A — deterministic in-memory mock (already shipped, `b5762c6`). This ticket is the real on-chain EVM leg, diff-tested against that mock's semantics.

## Purpose

Real Solidity HTLC contract deployed to Ethereum Sepolia testnet, plus a
Web3.py adapter that drives it — `lock` / `claim` / `refund` / `getStatus`
against an actual chain instead of the in-memory mock. Same semantics as
`server/bridge_htlc.py` (T3.4-A): `sha256(preimage) == hashlock`,
`msg.sender == recipient` on claim, absolute-timestamp `timelock`,
one-way state machine `EMPTY → LOCKED → CLAIMED | REFUNDED`.

Used as the ground-truth EVM leg for a two-chain atomic swap (Casper +
EVM), and as the diff-test target: on the same `(preimage, hashlock,
timelock)` inputs, this contract's accept/reject decisions must match
`bridge_htlc.py`'s pure state machine byte-for-byte.

## Contract

`contracts/HTLC.sol` — one instance per swap leg (deploy fresh per leg,
mirrors "one `HTLCLeg` per swap side" from the mock).

- `lock(bytes32 hashlock, uint256 timelock) payable` — escrows `msg.value`
  for `recipient` (set at construction). Reverts `AlreadyLocked`,
  `ZeroAmount`, `ZeroRecipient`, `TimelockInPast`.
- `claim(bytes preimage)` — pays out to `recipient` iff
  `sha256(preimage) == hashlock`, `msg.sender == recipient`,
  `block.timestamp < timelock`. Reverts `NotLocked`, `NotRecipient`,
  `TimelockExpired`, `PreimageMismatch`.
- `refund()` — returns escrow to `sender` iff `block.timestamp >= timelock`,
  `msg.sender == sender`. Reverts `NotLocked`, `NotSender`,
  `TimelockNotExpired`.
- `getStatus()` — view mirroring the mock's leg status dict
  (`sender, recipient, hashlock, timelock, amount, status`).

Uses `sha256` (not `keccak256`) for the hashlock so the identical
preimage/hash pair from a Casper leg (also sha256, see `bridge_htlc.py`)
works verbatim on both sides of the swap.

## Adapter

`server/bridge_evm_adapter.py` — Web3.py adapter with the interface:

- `connect()` — RPC connection with fallback across public Sepolia endpoints.
- `load_deployment()` — reads `T3.4-B-deployment.json`.
- `get_contract(w3, deployment)` — bound contract instance.
- `evm_lock(w3, acct, contract, hashlock_hex, timelock, amount_wei)`
- `evm_claim(w3, acct, contract, preimage)`
- `evm_refund(w3, acct, contract)`
- `evm_status(contract)` — dict mirroring `getStatus()`
- `sha256_hashlock(preimage)` — hashlock helper matching the contract's hash choice
- `EvmAdapterError` — raised on any revert, decoded from the contract's
  custom Solidity errors (e.g. a failed `claim()` gas-estimate against
  `PreimageMismatch()` surfaces as `EvmAdapterError("reverted: PreimageMismatch")`)
  rather than leaking a raw eth-abi selector.

## Diff-testing against the T3.4-A mock oracle

`bridge_htlc.py`'s pure state machine is the reference oracle: given the
same `(preimage, hashlock, timelock)` tuple, the mock's
`propose → lock → claim/refund` decision sequence must match this
contract's accept/reject sequence exactly. Both:

- Accept `claim()` iff `sha256(preimage) == hashlock` and not expired.
- Reject a forged preimage unconditionally, regardless of timing.
- Reject `claim()` at/after `timelock`; accept `refund()` only at/after `timelock`.
- Never allow a mixed outcome (claim after refund, or vice versa) — the
  state machine is one-way in both implementations.

Manual diff-test procedure: run the same `(preimage, timelock_offset)`
fixture through `bridge_htlc.py`'s in-memory leg and through
`bridge_evm_adapter.py` against Sepolia; assert identical `status` and
identical reject/accept decision at every step. Not yet automated as a
single parametrized test (future follow-up) — today it's verified by
inspection: both implementations share the same three revert conditions
on `claim` (`NotLocked`/`not_locked`, `TimelockExpired`/`timelock_expired`,
`PreimageMismatch`/`preimage_mismatch`) and the same two on `refund`
(`NotSender`/wrong signer, `TimelockNotExpired`/`timelock_not_expired`).

## Known operational note

Public Sepolia RPC nodes (no API key) occasionally show nonce lag across
different backend nodes behind the same hostname — a just-broadcast
transaction can appear "pending" on one node and "not found" on another
for up to ~60–90 seconds before the mempool propagates fully. This is
RPC-infrastructure latency, not a wallet or contract issue: balances and
nonces settle correctly once propagation completes. The adapter's
`evm_lock`/`evm_claim`/`evm_refund` calls use `wait_for_transaction_receipt`
with a 180s timeout to absorb this.
