# T3.4-A — HTLC atomic-swap bridge (mock)

**Status:** ✅ shipped in commit branch `tier-wow-and-3/main-block`.
**Sibling ticket:** T3.4-B — real Sepolia bridge (separate, follow-up).

## Purpose

Deterministic, in-memory Hash Time-Locked Contract state machine that
mirrors the semantics of a real cross-chain atomic swap between Casper
(chain `casper`) and an EVM chain (chain `evm-mock`). Zero I/O, zero
network, byte-for-byte reproducible from `(initiator, counterparty,
amounts, hashlock, timelocks)`.

Used for:

* SDK / agent-side flows and integration tests that need bridge
  semantics without gas or an RPC node.
* Judges reproducing an atomic-swap demo end-to-end with a single
  Python process.
* Reference oracle for T3.4-B (real Sepolia adapter): the on-chain
  behaviour of the Rust/Solidity implementation must match the
  decisions of this state machine byte-for-byte on the same inputs.

## Atomic-swap protocol (primer)

Two independent chains, one shared secret. Alice holds asset A on
Casper; Bob holds asset B on EVM. They want to swap without a trusted
third party.

1. Alice picks a random 32-byte preimage `s`, publishes
   `H = sha256(s)`.
2. Alice locks A on Casper with hashlock `H`, timelock `T_a` (farther).
3. Bob sees `H`, locks B on EVM with the same `H`, timelock `T_b`
   (nearer, `T_b < T_a`).
4. Alice claims B on EVM by revealing `s` — this publishes `s` on
   EVM (visible to Bob).
5. Bob observes `s` on EVM, uses it to claim A on Casper before `T_a`.

## Safety invariants (enforced)

| Invariant | How it's enforced |
|-----------|-------------------|
| `T_b < T_a` | `verify_timelock_ordering()` in `initiate_swap` |
| Either both claim or both refund | State machine: `CLAIMED`/`REFUNDED` are terminal; the observer/summary flags any mixed outcome as `safety_violation: true` (which the tests assert never happens on well-formed flows) |
| Preimage integrity | `claim` recomputes `sha256(preimage)` and rejects unless it equals the leg's `hashlock_hex` — no preimage from one swap can ever claim a different swap |
| No race on lock | `lock` requires `now < timelock`; expired locks are rejected |
| No race on claim | `claim` requires `now < timelock`; late claims are rejected (`timelock_expired`) |
| Only after timelock refund | `refund` requires `now >= timelock` |
| Idempotency | `lock` on a `LOCKED` leg is a no-op; `claim`/`refund` on already-terminal states raise typed rejections |

## State machine

```
    initiate(side)      lock(side)          claim(side, preimage)
INIT ─────────────► PROPOSED ────────► LOCKED ─────────────────► CLAIMED
                                          │
                                          │  refund(side) after timelock
                                          ▼
                                       REFUNDED
```

## Reject codes (typed)

`preimage_mismatch`, `timelock_not_expired`, `timelock_expired`,
`already_claimed`, `already_refunded`, `not_locked`, `not_proposed`,
`unknown_leg`, `leg_already_exists`, `invalid_hashlock`,
`invalid_amount`, `timelock_ordering`.

Codes are stable — SDK consumers can match against them.

## API surface (`/bridge/htlc/*`)

| Method | Path | Purpose |
|-------|------|---------|
| POST  | `/bridge/htlc/preimage/new`         | Helper: generate `(preimage, hashlock)` for demos |
| POST  | `/bridge/htlc/initiate`             | Create both legs as `PROPOSED` |
| POST  | `/bridge/htlc/legs/{leg_id}/lock`   | `PROPOSED → LOCKED` |
| POST  | `/bridge/htlc/legs/{leg_id}/claim`  | `LOCKED → CLAIMED` (preimage reveals) |
| POST  | `/bridge/htlc/legs/{leg_id}/refund` | `LOCKED → REFUNDED` (after timelock) |
| GET   | `/bridge/htlc/legs/{leg_id}`        | Fetch a single leg |
| GET   | `/bridge/htlc/swaps/{swap_id}`      | Fetch a swap with both legs |
| GET   | `/bridge/htlc/swaps/{swap_id}/summary` | `atomic_outcome` ∈ {completed, aborted, in_progress}, `safety_violation` flag, revealed preimage |
| GET   | `/bridge/htlc/swaps`                | List all swaps in the registry |

Status codes: `201` on `initiate`, `200` on transitions, `404` for
unknown ids, `409` for state conflicts / timelock races, `400` for bad
inputs, `422` for pydantic validation.

## Determinism guarantees

* `sha256_hex`, `compute_hashlock` → pure.
* `_leg_id`, `_swap_id`, `_mock_tx_hash` → sha256 of the input tuple
  (see the module for the exact preimage). Two independent processes
  starting from identical inputs produce identical ids and identical
  mock tx hashes — this is required so that T3.4-B can regression-test
  its Rust implementation against Python fixtures generated here.
* No wall-clock reads inside the state machine; `now_ms` is always
  passed in. API layer uses `time.time()` as the default; test suites
  override with `T0 = 1_700_000_000_000`.

## Tests

`tests/test_bridge_htlc.py` — 37 unit tests including:

* Pure helpers (hashlock, ordering, amount validation).
* State transitions: `initiate`, `lock`, `claim`, `refund` — happy
  path, idempotency, all typed rejections.
* Full atomic-swap flow (`test_atomic_swap_full_flow`) with 4-step
  reveal sequence.

  * `test_property_happy_path_always_completes` — 40 examples: for

  * `test_property_forged_preimage_never_claims` — 30 examples: no
    non-matching preimage ever produces `CLAIMED`.
* Deterministic tx-hash reproducibility across separate registries.

`tests/test_bridge_htlc_api.py` — 19 API tests including all HTTP
status codes, initiate validation, full HTTP flow end-to-end, list
endpoint, summary endpoint with `in_progress`/`completed` transition.

## Migration path — T3.4-B (real Sepolia)

* Introduce `EvmAdapter` protocol with methods
  `lock(recipient, hashlock, timelock, value) -> tx_hash`,
  `claim(tx_hash, preimage) -> tx_hash`,
  `refund(tx_hash) -> tx_hash`, `get_state(tx_hash) -> LegStatus`.
* Implement two concrete adapters:
  * `MockEvmAdapter` — wraps the current `HTLCRegistry` (used by
    tests + the bridge-mock endpoints; behaviour unchanged).
  * `SepoliaEvmAdapter` — signs & submits transactions to a real
    HTLC contract on Sepolia via `web3.py`. Needs a testnet wallet
    (Quentin will fund) and a deployed HTLC contract address.
* Sign transactions with `eth-account`; RPC via
  `https://sepolia.infura.io/v3/<key>` (add key to vault under
  `team.infura_sepolia`).
* The Casper leg keeps using the sandbox / real Casper adapter (out
  of scope for T3.4-B — that's already handled by `cross_chain.py`).
* Property tests from `test_bridge_htlc.py` are replayed against the
  Sepolia adapter in a nightly job with a small notional (dust) —
  identical decisions on identical inputs prove parity.

## Non-goals (of this ticket)

* Real EVM RPC. Deferred to T3.4-B.
* Zero-knowledge preimage schemes.
* Adaptor signatures / scriptless scripts.
* Multi-hop routing.
