# Testimonial intake (post-pilot)

**When to send:** 48h after the pilot user hits their first
`release()` or `dispute()`. Not before.

**How to send:** Slack DM or email — whichever channel they used for
the pilot. Never a form. Never a marketing pipeline.

**How to use:** with explicit written permission, quote 2–3 sentences
verbatim on the hackathon submission page under a "What pilot users
say" section. Attribution: name + project + optional headshot.

## The 6 questions

```
1. In one sentence — what was the flow you tried?
   (e.g. "Two LangChain agents negotiating for scraper hours,
    paid via escrow with a dispute fallback.")

2. What was the time from "pip install" to first working escrow?
   (Honest number. If it took 30 minutes, say 30 minutes.)

3. What was the ONE thing that surprised you — good or bad?

4. Would you use AgentEscrow402 for a real (production) flow today?
   Yes / No / Depends on:_______

5. If we could fix one thing before you'd use it in production,
   what would it be?

6. Optional — a 2-3 sentence quote we could put on the submission
   page, credited to you. (Only include this if you're comfortable
   being publicly associated with the pilot.)
```

## Follow-up

- **Answers land:** thank them, ask if they'd take a follow-up call
  in 4 weeks to see what changed on their side.
- **No answer in 48h:** one gentle nudge, then drop it. A pilot user
  who doesn't answer is a pilot who churned; forcing a testimonial
  is a hackathon-losing move.

## Non-goals

- Case studies, marketing collateral, sales narratives — post-hackathon.
- Anonymized quotes ("An agent developer said...") — either name-and-project
  or don't quote.
- Bribing for testimonials — we said $50 testnet credit up front, that's
  the deal.
