# On-chain Deploy — Owner Runbook

> **Audience.** The person holding the deploy key for the AE402
> Casper contracts. Every step here mutates chain state or a
> production manifest — read carefully before you run.
>
> **Prerequisites.** A tagged release in `main`, a green
> `on-chain preflight` CI run against it, and the current deploy
> keypair.

---

## 1. The preflight gate

Before any `casper-client put-deploy`, run:

```bash
python scripts/onchain_preflight.py --verbose
```

Exit code `0` = every check passed:

- **discovery** — packaged tx wasms + built contract wasms both present.
- **size_ceiling** — every WASM ≤ 700 KiB (300 KiB below Casper 2.0's hard 1 MiB limit).
- **magic_bytes** — every WASM starts with `\x00asm\x01\x00\x00\x00` (WebAssembly binary format). Catches truncation.
- **entry_points** — packaged tx wasms export `call` (session-code convention). Contract wasms export at least one `_ep_*` / `entry_point_*` / `call` symbol (Odra convention).
- **deployment_manifest** — `deploy-out/onchain.json` lists every deployed contract, every entry has a valid 64-hex `contract_hash`, no two entries share a hash.

**Any non-zero exit blocks the deploy.** Fix the finding, rebuild, re-run preflight.

The same script runs in CI on any PR that touches `contracts/`, `server/casper_tx/`, `deploy-out/`, or the preflight itself. A red preflight blocks merging into `main`.

Machine-readable variant (used by CI):

```bash
python scripts/onchain_preflight.py --json > preflight-report.json
```

## 2. Deploy sequence

### 2.1 Build (once per tag)

```bash
just build           # or: make contracts && make wasm-cli
```

Produces:

- `contracts/target/wasm32-unknown-unknown/release/*.wasm` — the contract binaries themselves.
- `server/casper_tx/*.wasm` — packaged session-code payloads the backend sends per user call.

### 2.2 Preflight (mandatory)

```bash
python scripts/onchain_preflight.py --verbose
```

Green? Continue. Red? Fix, rebuild, restart at 2.1.

### 2.3 Testnet dry-run

```bash
casper-client put-deploy \
    --node-address <TESTNET_NODE_ADDR> \
    --chain-name casper-test \
    --secret-key <DEPLOY_KEY_PATH> \
    --session-path server/casper_tx/deploy_escrow_manager.wasm \
    --session-arg 'admin:key=<ADMIN_KEY>' \
    --payment-amount 300000000000
```

Wait for the deploy to finalize. Grab the resulting `contract_hash`.

### 2.4 Verify state on testnet

```bash
casper-client query-global-state \
    --node-address <TESTNET_NODE_ADDR> \
    --state-root-hash "$(casper-client get-state-root-hash …)" \
    --key hash-<contract_hash>
```

The result must show the expected named keys (`escrow_purse`, `dispute_registry`, etc.). Anything missing = re-check the contract's `install()` entry-point implementation.

### 2.5 Update `deploy-out/onchain.json`

The canonical deployment manifest. Add or update the entry for the
newly-deployed contract:

```jsonc
{
  "contracts": {
    "escrow_manager_v9": {
      "network": "casper-test",
      "contract_hash": "hash-<64hex>",
      "contract_package_hash": "hash-<64hex>",
      "deployed_at": "2026-07-26T…",
      "deploy_hash": "<64hex>"
    }
  }
}
```

Commit + push. The next preflight run picks up the change.

### 2.6 Redeploy anything that pins the hash

- Backend env vars: `AE402_ESCROW_CONTRACT_HASH`, `AE402_MANAGER_CONTRACT_HASH`, `AE402_INSURANCE_CONTRACT_HASH`, `AE402_VRF_CONTRACT_HASH`.
- Frontend: `deploy-out/frontend-manifest.json` (regenerated by `python scripts/generate_frontend_manifest.py`).
- Docs: any hash quoted in `docs/api/` or `docs/deployment/` gets a search-and-replace.

## 3. Mainnet deploy checklist

Mainnet deploys are gated by everything in §1 + §2 PLUS:

- [ ] External audit report attached to the PR that produced this build (Phase 3 exit — see `docs/POST_HACKATHON_ROADMAP.md`).
- [ ] `main` at the exact tag being deployed, no uncommitted changes.
- [ ] Preflight run against the exact tag artefacts, JSON report committed alongside the manifest update.
- [ ] Two-person approval: at least one reviewer other than the deployer signs the deploy PR.
- [ ] Rollback plan documented in the deploy PR body (which prior tag we roll back to, and how the backend env vars flip).
- [ ] Post-deploy verification steps queued: `/health`, `/metrics`, `make judge-lite`, `make judge-demo`.

Do not deploy to mainnet without all six.

## 4. Failure modes we have hit before

- **Size ceiling.** A debug build of the escrow contract shipped a 1.2 MiB WASM once. The mainnet deploy would have silently failed. Preflight catches this now.
- **Duplicate contract_hash.** A copy-paste in `deploy-out/onchain.json` at some point had two contracts pointing at the same hash. Backend picked whichever hit the map first. Preflight catches this now.
- **Truncated WASM.** A partial S3 upload of the built artefact corrupted `escrow_funder.wasm`. Deploy went through, but every `call` panicked. Preflight catches this now via magic-byte check.
- **Missing manifest entry.** Contract was deployed but the manifest never updated — backend fell back to a stale hash. Preflight catches this now (packaged tx present in dir, contract missing from manifest).

Every one of these turned into a red preflight after the fact; the script is the codification of the post-mortem for each.
